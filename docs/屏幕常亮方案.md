# ReadBook 屏幕常亮方案

> 日期：2026-10-27　|　状态：已定稿，待实施
> 决策：前端来源聚合 + 后端单开关命令；桌面侧用 `keepawake` crate（RAII guard），iOS 预留 no-op 占位。

## 1. 需求与范围

- 文本阅读**滚屏播放**与**页模式定时翻页**期间保持屏幕常亮（不进屏保/待机/显示休眠）。
- 常亮能力**开放给全部插件**（内置与外部）：图片查看（幻灯播放、自动滚屏）、视频查看（播放中）等场景由插件自行调用；插件视图关闭时宿主自动释放其持有的常亮。
- 用户设置「滚屏/播放时保持屏幕常亮」，默认开启；关闭后行为完全短路。
- 非目标：不处理窗口隐藏到托盘时的特殊语义（播放状态即依据）；不做系统休眠（合盖/手动睡眠）抑制之外的电源管理功能。

## 2. 选型记录（keepawake vs tauri-plugin-nosleep）

| 维度 | keepawake 0.6.1（选定） | tauri-plugin-nosleep 2.0.0-beta.1 |
|---|---|---|
| 维护 | 活跃（2026-08 更新），318k 下载，公共仓库 | 2024-02 停更，绑定 tauri 2.0.0-beta.5，crates.io 无仓库链接 |
| Linux 后端 | zbus 5 纯 Rust（零系统库依赖）；`org.freedesktop.ScreenSaver` + **logind Inhibit（fd 持有锁）**，无 DE 的 WM 也生效 | `dbus` 0.9 = libdbus FFI（编译需系统库）；GNOME/freedesktop PM/ScreenSaver 接口，无 logind |
| 释放语义 | RAII guard Drop 即释放；logind 锁随 OwnedFd 丢弃自动释放 | cookie 手动释放；macOS 自述「持续到进程退出」 |
| iOS | 不支持，但 `compile_error!` 明确 → target 门控依赖即可干净隔离 | `nosleep` 在 iOS 无任何导出，插件 lib.rs 无条件引用 → 整 crate 在 iOS 编译失败 |

iOS 适配：两者均无 iOS 后端。iOS 落地时在本方案的平台分发模块加 `objc2-ui-kit` 分支（`UIApplication.idleTimerDisabled`，经 `run_on_main_thread`），命令签名与前端零改动。与 iOS 方案中 tray-icon/trash 的 target 门控先例同模式。

Web Screen Wake Lock API 不采用：WebKitGTK（Linux 主力平台）未实现。

## 3. 架构

**前端聚合 + 后端单开关。**

```
reader.ts 滚屏/定时翻页 ──┐
image-viewer 幻灯/自动滚屏 ├─ holdAwake(source,on) ──▶ Set<来源> 非空?
video-viewer 播放中       ─┘        │                  且设置开启
                                    ▼
                          api.setKeepAwake(bool)（状态变化时才调）
                                    ▼
                     Rust 命令 set_keep_awake(on)（幂等）
                                    ▼
              desktop: keepawake guard 建立/丢弃（RAII）
              其他目标（iOS）: no-op 占位
```

聚合放前端而非 Rust 计数：后端接口最简（单 bool）、浏览器 mock 天然 no-op、聚合逻辑纯 TS 可在演示模式验证。多来源并发安全：集合空了才关，谁最后结束谁关灯。

## 4. Rust 侧

新文件 `src-tauri/src/wake.rs`：

- `Cargo.toml`：
  ```toml
  # 屏幕常亮：仅桌面目标（iOS 不支持，见 docs/屏幕常亮方案.md；门控先例同 tray-icon/trash）
  [target.'cfg(any(target_os = "linux", target_os = "macos", target_os = "windows"))'.dependencies]
  keepawake = "0.6"
  ```
- `WakeState`（`Mutex<Option<keepawake::KeepAwake>>`）经 `.manage()` 注册。
- 命令 `set_keep_awake(on: bool)`：
  - `on=true` 且 guard 为空：`keepawake::Builder::default().display(true).app_name("ReadBook").reason("滚屏/播放中").create()`；已存在则跳过（幂等）。
  - `on=false`：置 `None`（Drop 释放 logind fd / IOKit 断言）。
  - 创建失败（如无 D-Bus 的环境）**只 log 不报错**：屏保抑制失败不阻断阅读，命令恒返回 `Ok`。
- 平台分发的 cfg 与 Cargo 门控完全一致（`any(target_os = "linux"|"macos"|"windows")`），不用 `cfg(desktop)` 以防非三大桌面目标误入；其余目标 no-op 占位，注释写明 iOS 的 objc2-ui-kit 方案。
- `lib.rs` 注册 `mod wake;` 与命令。

## 5. 前端侧

新文件 `src/keepawake.ts`：

```ts
holdAwake(source: string, on: boolean)     // 持有/释放来源
releasePluginAwake(pluginId: string)       // 清掉 plugin:<id> 来源（视图关闭兜底）
setKeepAwakeEnabled(v: boolean)            // 设置开关：翻转标志并强制同步
```

- 来源命名：阅读侧 `"reading"`，插件侧 `plugin:<id>`（每插件一个来源，插件内部自行 OR）。
- 同步规则：来源集合或设置变化时，目标状态（`enabled && sources.size > 0`）与后端当前状态不同才调 `api.setKeepAwake`；失败仅 `console.warn`。
- `api.ts` 增加 `setKeepAwake: (on) => invoke("set_keep_awake", { on })`；`mock_backend.ts` 加 no-op 分支。

## 6. 接入点

| 位置 | 挂接 |
|---|---|
| `reader.ts` `startScroll`/`stopScroll` | `holdAwake("reading", …)`。连续滚屏与页模式定时翻页共用这一对启停函数，一处覆盖两个场景 |
| `registry.ts` ctx 构造 | `setKeepAwake: (on) => holdAwake(\`plugin:${owner.id}\`, on)`；`deactivateActive()` 与切换插件时 `prev.deactivate` 路径均调 `releasePluginAwake(id)`——外部插件忘关也不会永久常亮 |
| `plugins/types.ts` | `PluginOpenContext` 加 `setKeepAwake(on: boolean): void`。向后兼容（旧插件不用即无感知），插件 API 大版本仍为 1 |
| `image-viewer.ts` | 幻灯启停、自动滚屏启停处统一调 `updateAwake() → ctx.setKeepAwake(slideOn \|\| scrollOn)` |
| `video-viewer.ts` | 现有 `play`/`pause`/`ended` 事件监听处加 `ctx.setKeepAwake(!paused && !ended)`；切集自然触发事件，视图关闭由宿主兜底 |
| `types.ts` `Settings` + `app.ts` 默认值 | `keepAwake: boolean`，默认 `true`；启动时 `setKeepAwakeEnabled(s.keepAwake)` |
| `menubar.ts` 视图菜单 | autoRestore 旁加勾选项「滚屏/播放时保持屏幕常亮」 |

## 7. 错误处理

| 情形 | 行为 |
|---|---|
| 后端 guard 创建失败（无 D-Bus 等） | log 降级，命令返回 Ok，阅读不受影响 |
| 前端 invoke 失败 | `console.warn`，状态机不回滚（下次变化重试） |
| 进程退出/崩溃 | RAII：logind fd 丢弃 / IOKit 断言随进程释放，无需清理代码 |
| 外部插件忘关 | `deactivateActive` 兜底 `releasePluginAwake` |
| 用户关闭设置 | 短路立即关；来源集合保留，重新开启后按当前来源恢复 |

## 8. 验证

项目无前端测试 runner，遵循现状手工验证：

1. `npm run tauri dev`，Space 滚屏 → `systemd-inhibit --list` 出现 readbook 的 `block idle` 抑制项；停止滚屏后消失。
2. 页模式（P）定时翻页同样验证。
3. 图片幻灯、自动滚屏、视频播放各自验证；暂停/播完/关闭视图后释放。
4. 视频播放中关闭「保持屏幕常亮」设置 → 立即释放；重新开启 → 恢复。
5. 浏览器 mock 模式（`npm run dev`）滚屏无报错（no-op）。
6. `cargo check`：Linux 目标通过；`cargo check --target aarch64-apple-ios`（如本机装有 target）验证 iOS 门控无编译问题。
7. 插件视图关闭后 `systemd-inhibit --list` 无 readbook 残留。
