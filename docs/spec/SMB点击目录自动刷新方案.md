# SMB 点击目录自动刷新方案

> 日期：2026-10-31　|　状态：已实施（2026-10-31，实施记录见 `docs/plans/2026-10-31-SMB点击目录自动刷新.md`，提交 31b6da5）
> 决策：点击目录即失效该目录缓存并从服务器重拉；全量 🔄 按钮与右键「刷新目录」保留兜底；移动弹窗内导航仍走缓存。

## 1. 需求与范围

- 现状：远程面板目录列表有会话内缓存（`childrenCache`），点击目录命中缓存即返回，远端文件变动后看到的仍是旧列表；仅有 🔄 全局刷新（清全部缓存）与目录右键「刷新目录」两个入口，不易发现且语义偏重。
- 目标：**点击树中目录（含服务器根）时自动重拉该目录**——丢弃该目录自身缓存、从服务器取最新条目后渲染，下方文件列表同步拿到新数据。
- 非目标：不做定时/时效性缓存过期（如 30 秒 TTL）；不改移动弹窗（`pickSmbDir`）内的导航行为（继续走缓存，弹窗里快速翻目录不打网络）；后端零改动。

## 2. 设计

仅改 `readbook/src/smb.ts`：

1. **新增 `dropDirCacheOnly(dir)`**：只失效该目录自身的缓存键，与现有 `dropDirCache`（删除/重命名等变更场景，含子树清扫）区分。服务器根 `smb://<id>` 与规范共享根 `smb://<id>/<share>` 是同一目录的双键（见 `loadChildren` 注释），仍要一起删。不复用 `dropDirCache` 的原因：它对任意目录都会连带删共享根双键，点击深层目录会误失效共享根缓存、多打一次无谓网络请求。
2. **树点击处理**（`bindRowEvents` 目录分支）：展开/收起逻辑不变，点击目录先 `dropDirCacheOnly(path)` 再 `renderAll()`——已展开目录子项重拉，`selectedDir` 指向的下方列表自然重拉。
3. **右键「在下方列出文件」**（`selectDir`）同样先失效再渲染。
4. **渲染重入守卫**：`renderAll` 加模块级序号，`renderTree`/`renderList` 在 await 网络后检查序号、过期则放弃写 DOM。重拉把网络往返落在点击路径上，快速连点两个目录时旧请求不得回写界面（`pickSmbDir` 已有同款 `seq` 模式）。
5. **失败重试**：`loadChildren` 出错时缓存空数组；点击强制失效后，下次点击自动重试，无需额外逻辑。

## 3. 验证

- `npm run build` 过 tsc（前端改动，无 Rust 面）。
- 真机 NAS 手动验证：点击目录重拉（远端增删文件后点击即见变化）、断网点击出 toast 且再次点击重试、快速连点两个目录界面不串台、移动弹窗翻目录仍秒开。
