# 全屏沉浸模式方案

日期：2026-10-28

## 背景与目标

现有全屏（`F11` / 工具栏 ⛶ / 菜单「全屏阅读」）只是 `requestFullscreen()` 把窗口铺满，菜单栏、工具栏、状态栏、打开着的侧边栏、插件内工具栏全部原样可见（styles.css 里 `body.fullscreen` 隐藏规则是死代码，类名从未被挂上）。视频插件桌面端 ⛶ 则是只把视频画面本身全屏。

目标：以**公共功能**重新提供全屏——

1. 阅读/播放区域铺满整窗；菜单栏、工具栏、状态栏、侧边栏（含插件内工具栏）全部隐藏并**吸附在屏幕边缘**
2. 鼠标碰到屏幕边缘时对应栏滑出可操作，移开后自动收回
3. `F11` / `Esc` 退出；视频插件全屏按钮统一走公共模块
4. 同时去掉「滚屏时鼠标上下位置调速」，速度只由速度栏（速度标签弹层、`1-9`、`+`/`-`）控制

## 方案选型

**选定：阅读区 fixed 铺满 + 各栏 transform 吸附**（对比过负 margin 挤压布局、`display:none` 硬切两个方案：前者动画与吸附都要另做且踩项目已知的 margin 陷阱；后者不满足吸附诉求）。要点：

- `body.fs-immersive` 新类（与视频插件触屏退役的 `body.immersive` 区分）
- `#reader-container` 沉浸时 `position: fixed; inset: 0`，插件视图宿主在内随之铺满
- 各栏 `transform` 滑出屏幕缘，动画走 `transition: transform`（避开 margin+var() transition 卡死陷阱）
- 全屏模块在四条屏幕边缘布置热区，鼠标碰边挂 `show-top/right/bottom/left` 类滑回对应栏

## 模块设计：`src/fullscreen.ts`（公共功能）

```
initFullscreen()      建 4 条热区、绑 fullscreenchange / resize 对账与 document 级 mouseover/mouseout
isImmersive()         !!document.fullscreenElement || body.fs-immersive
toggleFullscreen()    沉浸中 → exit，否则 enter
enter()/exit()        挂/摘 body.fs-immersive + 全屏：真 Tauri 桌面走原生窗口全屏
                      （getCurrentWindow().setFullscreen，macOS 标准 Space 过渡、不在原桌面
                      残留窗口）；浏览器演示走 requestFullscreen/exitFullscreen，
                      被拒（非用户手势等）静默降级为纯 CSS 沉浸
```

- **不 import app.ts**（避免循环依赖）；状态变化派发 `rb-fullscreen-changed` 事件，app.ts 监听后 `updateUI()` 同步工具栏按钮与菜单勾选态
- `app.ts` 的 `isFullscreen`/`toggleFullscreen` 改为委托本模块再导出（menubar/shortcut 调用点不变）
- `app.handleEscape` 链首（编辑弹窗判断之后）插入：沉浸中 → 退出全屏并 return；web 全屏激活时 Esc 由浏览器原生消费直接退出，经 `fullscreenchange` 同步清理类
- `shortcut.ts`：`F11` 分支移到 `plugins.isActive()` 屏蔽之前（插件视图内也能全屏）

## 呼出交互（热区与 show-* 类）

- 热区：4 条 `position: fixed` 条，上下高 8px、左右宽 6px（左右窄以减少对阅读区右缘滚动条的遮挡，滚动条仍有约一半宽度可拖），`z-index: 350`，非沉浸 `display:none`
- 判定用 document 级 `mouseover`/`mouseout` + `closest()`，每边一个命中集合：
  - 上：热区、`#menu-bar`、`#toolbar`、`.plugin-topbar`、`#menu-dropdown`（下拉菜单悬停不收）
  - 下：热区、`#status-bar`、`.plugin-bottombar`
  - 左：热区、`.side-panel.panel-left`（文件夹栏，开着才可见）
  - 右：热区、右侧 `.side-panel`（开着才可见）
- `mouseout` 用 `relatedTarget` 判重（仍在集合内不动作），离开后延时 300ms 摘 `show-*`
- 进入全屏时 toast 一次：「全屏模式：F11/Esc 退出，鼠标碰屏幕边缘呼出各栏」

## CSS 吸附规则（styles.css 新增一节）

- `body.fs-immersive #reader-container { position: fixed; inset: 0; z-index: 300; margin: 0; }`，同时覆盖 `body.panel-open` / `body.folder-open` 的 margin 让位（两者均归零）
- 菜单栏、工具栏：`position: relative; z-index: 400`，`translateY` 滑出窗顶（工具栏额外多移一个菜单栏高度）；状态栏 `translateY(100%)` 滑出窗底；`.show-top` / `.show-bottom` 时 `transform: none`
- 侧边栏：右侧面板 `translateX(100%)`、文件夹栏 `translateX(-100%)` 吸附，`show-right` / `show-left` 滑回，覆盖在阅读区上（不动 margin）；面板互斥/关闭逻辑不变
- 插件约定类：沉浸时 `.plugin-topbar` 改 `position: absolute` 吸附 `#plugin-view-host` 上缘（脱离文档流，stage 自动占满），`translateY(-100%)` 滑出；`.plugin-bottombar` 对称吸下缘；`show-top` / `show-bottom` 滑回
- 查找栏：沉浸时钉 `top: 12px` 右上常显（自带 ✕），重置 panel-open 的右让位
- 全部过渡只用 `transition: transform`；热区无过渡
- 视频/图片插件工具栏 z-index 在宿主内抬到热区之上，保证悬停保持展开

## 插件改造

- **图片查看**：`.imgv-bar` 挂 `plugin-topbar`
- **视频查看**：`.vv-bar` 挂 `plugin-topbar`、`.vv-seekrow` 挂 `plugin-bottombar`；`toggleFullscreen()` 删 stage 全屏分支与 `immersive` 触屏兜底（`body.immersive` 类与清理代码退役），直接调公共模块——触屏下 requestFullscreen 被拒自动降级 CSS 沉浸，行为不丢；视频插件自己的 `F` 键同走公共模块
- **外部插件**：`docs/插件开发.md` 补约定——工具栏挂 `plugin-topbar` / `plugin-bottombar` 即自动获得吸附行为；不挂则沉浸时保持常显（兼容不破坏）

## 移除鼠标调速（独立小改）

- `reader.ts`：删 `mouseFactor` 与 `onMouseMove` 中的调速赋值（保留滚屏时移动鼠标短暂显示光标 1.2s 的行为）；`loop()` 直接 `speed * dt / 1000`；`startScroll` 删 `mouseFactor = 1`；`speed` 注释去掉「鼠标位于屏幕中部时」
- `app.ts`：开始滚屏 toast 删「鼠标上下移动可调速」；速度弹层标签「滚屏速度（鼠标上下位置仍可临时调速）」→「滚屏速度」
- `README.md`：「连续滚屏」行删「鼠标纵向位置实时调速」；「全屏阅读」行改为新行为描述；help 弹窗（menubar.ts）同步检查

## 边界情况

- 桌面端（Tauri）弃用网页元素全屏：WKWebView（macOS）的 requestFullscreen 会另开全屏窗口、原窗口残留在原桌面；GTK/Windows 亦有各自怪癖。统一走原生窗口全屏（capabilities 已授 core:window:allow-set-fullscreen）
- 系统侧进出全屏（macOS 绿键/Ctrl+Cmd+F、Linux WM 全屏按钮）：resize 监听比对 isFullscreen() 与目标态 nativeWanted，仅实际态 ≠ 目标态时同步沉浸类（自身调用产生的中间态不动），系统侧进入也会自动进入沉浸
- requestFullscreen 被拒 → 纯 CSS 沉浸照常，`isImmersive()` 仍真，F11/Esc 可退
- 全屏中快捷键开面板（Ctrl+K 等）→ 面板吸附右缘碰边呼出
- 双页/页模式/滚屏在全屏下照常（同一元素仅容器满屏）；滚屏中鼠标停在边缘热区会呼出各栏（可接受的标准行为）
- 下拉菜单可锚定屏幕任意位置（状态栏编码切换、阅读区右键菜单、子菜单）：
  - 悬停下拉保持当前已展示边（1s 保持延时），不新增边
  - 从下拉移到普通内容后原已展示边按正常 300ms 延时收回
  - 从菜单主表移入子菜单（`.dropdown-sub`）时顶栏不收回（保持延时覆盖）
  - 从状态栏移入其下拉时状态栏不收回（1s 保持中）
- 呼出后的插件工具栏最边缘 6~8px 被热区覆盖（热区在根上下文层，插件栏封顶于阅读区堆叠上下文内），仅影响窄条点击，不影响悬停保持

## 验证

- `npm run build` 全绿（tsc 严格模式）
- `npm run dev` 浏览器手测：进退全屏、四边呼出/收回、侧边栏与插件栏吸附、下拉菜单悬停不收、速度 1-9 与速度栏调速、鼠标移动不再改变滚速
- `npm run tauri dev` 桌面端留用户验证：原生窗口全屏进出（macOS 不残留窗口、Linux WebKitGTK 正常）、Esc 原生退出、热区呼出、系统侧绿键退出后沉浸类同步摘除
